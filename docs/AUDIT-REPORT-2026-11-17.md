# تقرير تدقيق Atlas REIT

**التاريخ:** 17 نوفمبر 2026
**النطاق:** تاريخ التدقيق الأولي والتحديث المحلي على الفرع الحالي. هذا تقرير تسليم وليس شهادة جاهزية أو رأياً قانونياً/محاسبياً.

## الخلاصة التنفيذية

بدأ المستودع كتطبيق Next.js 15 لإعلانات العقارات ولوحة موظفين صغيرة. تطور محلياً تدريجياً ليشمل نماذج المالك/المحفظة/العقار/الوحدة، CRM، العقود، المالية، الصيانة، الإعدادات، الأدوار، بوابة المستأجر، التنبيهات والتدقيق. التغييرات تحافظ على التطبيق الحالي ولا تعيد إنشاءه من الصفر.

**الحالة: غير جاهز للإطلاق الإنتاجي.** لا اتصال أو تعديل لقاعدة إنتاج، لا نشر، لا إرسال بريد فعلي، ولا تغيير أسرار. اختبارات الأعمال والبناء والأنواع وتدقيق التبعيات نجحت محلياً؛ لم يُشغّل PostgreSQL المتوافق مع الإنتاج أو E2E، ومراجعة الصلاحيات/الترحيلات التشغيلية لم تكتمل.

## أساس المستودع والمراجعة الأولية

- Next.js App Router وReact وTypeScript وZod؛ `pg` لقاعدة PostgreSQL وPGlite للاختبارات المحلية.
- الموقع العام يعرض العقارات، تفاصيلها ومعرض الصور ونموذج الاستفسار. الإدارة الأصلية كانت للإعلانات والاستفسارات والمستخدمين.
- كان المخطط الأولي صغيراً (مستخدمون وإعلانات واستفسارات) دون عقود أو فواتير أو ضمان أو صيانة. أضيفت الكيانات والخدمات تدريجياً عبر migrations في `src/lib/migrate.ts`.
- حُذفت كلمات المرور الافتراضية؛ تهيئة المدير تتطلب كلمة مرور صريحة. عُزز فحص Origin وإبطال الجلسات وتحديد محاولات الدخول. عولجت تبعيات سابقة حتى أصبح `npm audit` بلا ثغرات في التشغيل الحالي.
- اللغة العربية وRTL والدينار الجزائري DZD معتمدون في الواجهة الحالية. يلزم قبل تطبيق ترحيل على بيانات فعلية تحديد عملة البيانات القديمة ومعدل التحويل المعتمد عند الاقتضاء، وعدم افتراض تحويل تلقائي.
- الصور العامة تمر عبر تخزين الصور/Blob؛ لا تستخدم آلية رفع الصور العامة لحفظ مستندات حساسة. يلزم اعتماد تخزين خاص وروابط مؤقتة وفحص ملفات قبل استخدامها لمرفقات قانونية أو مالية.

## القدرات التي أضيفت

- الملاك والمحافظ والعقارات والوحدات مع الإبقاء على معرفات وصلات الإعلانات العامة، وإدارة العملاء المحتملين والمراحل والزيارات.
- المستأجرون والعقود واعتماد/تفعيل، جدولة فواتير، منع تداخل الوحدة، طلب تجديد يحتفظ بتاريخ العقد السابق، وطلب إنهاء مبكر بموافقة منفصلة.
- الإنهاء يحتسب الفترة الحالية حسب الأيام الفعلية، ويعامل تاريخ النفاذ كأول يوم غير مشغول وغير محتسب؛ يحفظ سجل الفواتير الصادرة، ويوقف الاستحقاقات المستقبلية غير المكتسبة ويسجل التعديلات/الرصيد الدائن دون غرامة تلقائية. الاستثناءات التعاقدية قابلة للتسجيل وموافقة المدير مطلوبة.
- تسجيل دفعات جزئية وتخصيصها على الفواتير، ومراجعة مستقلة لطلبات رد/إلغاء الدفعات مع منع اعتماد مقدم الطلب.
- سجل قبض ضمان مستقل عن الإيجار، طلب اقتطاع موثق بمرفقات نصية وموافقة شخص آخر مخول، ورد كلي/جزئي مع منع تجاوز الرصيد.
- بوابة مستأجر مع عزل استعلامات حسب المستأجر وعقوده، دعوة واستعادة ذاتية بروابط عشوائية لمرة واحدة مخزنة كـhash، انتهاء وإبطال الرمز السابق، إجابات عامة لاستعادة كلمة المرور ومحدد معدل دائم في قاعدة البيانات. مزود الاختبار يحفظ الرسائل في outbox ولا يرسلها.
- تنبيهات داخل الإدارة لانتهاء العقود على 90/60/30 يوماً ومنع التكرار، مع إعداد Vercel Cron يومي. بريد التنبيه غير مفعل.
- صلاحيات أدوار على مسارات وصفحات رئيسية، سجل تدقيق، إعدادات سياسة قابلة للتعديل، وعرض أرصدة الدائنين دون مقاصّة تلقائية مع الفواتير.

تفاصيل قواعد الأعمال والقيود في `docs/ATLAS-REIT-RULES-STATUS.md`.

## استكمال أمني واختبارات إضافية — 17 نوفمبر 2026

- أُضيف رفض صريح للجلسة المفقودة/الملغاة إلى جميع route handlers تحت `/api/admin`, بدلاً من الاكتفاء بـmiddleware الذي يتحقق من توقيع JWT دون مراجعة إصدار المستخدم في قاعدة البيانات. اختبار ثابت يمنع إنشاء route جديد دون `getSession` وفحص null داخل handler.
- أُضيف اختبار كامل لمصفوفة الأدوار، وإعادة استخدام متزامنة لدعوة مستأجر (واحد فقط من الطلبين ينجح)، ومحدد معدل متوازي (خمسة مسموحة فقط).
- تحقّق TLS لشهادات Postgres أصبح مفعلاً افتراضياً للاتصالات غير المحلية. `PGSSL_CA` اختياري لشهادة CA خاصة؛ لا يتم تعطيل تحقق الشهادة.
- فحص HTTP محلي للبناء: صفحات قبول الدعوة/نسيت كلمة المرور/إعادة التعيين رجعت 200، وJWT صالح التوقيع لمستخدم غير موجود رُفض من API الإدارة بـ401. شُغّل بقاعدة PGlite مؤقتة وقيم اختبارية فقط، ثم أُوقف الخادم.

## ما يتطلبه أي انتقال إلى بيئة حقيقية

1. قاعدة PostgreSQL مؤقتة متوافقة مع إصدار الإنتاج: تشغيل كامل الاختبارات ومراجعة migrations/locks/قيود التداخل والأنواع العددية والتواريخ والتراجع، وعدم تمرير رابط إنتاج.
2. مراجعة أمنية مستقلة لكل صفحات وواجهات API وإجراءات الخادم، مع اختبارات سلبية للأدوار وعزل المستأجرين والرفع والمستندات والتقارير وإدارة الحسابات.
3. اختبارات E2E للبوابة العامة للدعوة/الاستعادة والدخول والإنهاء والتجديد والضمان والدفع، RTL، التكرار والإخفاقات والتزامن.
4. نسخة staging ونسخة احتياطية قابلة للاستعادة وخطة rollback، ومقارنة سجلية قبل وبعد migration. لا تحذف البيانات الموجودة.
5. تأكيد قانوني ومحاسبي محلي لنماذج العقود والاستثناءات والتناسب والضرائب والرسوم والإيصالات، وتحديد صلاحيات الاعتماد وسياسات الاحتفاظ بالمستندات.
6. عند تشغيل البريد: إعداد `EMAIL_PROVIDER=resend`, `RESEND_API_KEY`, `EMAIL_FROM`, و`APP_BASE_URL` عبر بيئة الأسرار خارج Git. `APP_BASE_URL` يجب أن يكون HTTPS في الإنتاج؛ عيّن `CRON_SECRET` لحماية Cron. لا توجد اعتمادات مختلقة أو مضمنة.

لم يتم تنفيذ أي من هذه الخطوات على الإنتاج. لا يُعلن الإطلاق قبل اجتيازها وموافقة المالك والمراجعين المختصين.

## 11. Google tenant sign-in and self-registration

- Added `/portal/register` with mailbox-confirmation OTP (six digits), single-use/expiry/attempt limits, HMAC digest at rest, and DB-backed rate limiting. A verified address attaches to one existing tenant record instead of duplicating it; a new verified address creates a tenant record without a lease. A disabled portal account is not reactivated by registration.
- Added optional Google OpenID Connect sign-in for tenant portal only, with signed state cookie, nonce, PKCE S256, Google ID-token signature/issuer/audience checks and verified-email requirement. It will create a tenant record when no existing matching record exists. Staff login remains email/password.
- Added configuration documentation for `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, callback URI, Resend mail provider, and OTP expiry. No OAuth credentials were supplied or added, so live Google consent/callback/token exchange was not exercised; deployment must configure the OAuth client and email provider.
- PGlite verifies registration-code HMAC/expiry/single-use, safe existing-tenant association, refusal to reactivate disabled accounts, and OAuth state/nonce/PKCE tamper detection. Local HTTP smoke confirmed the registration page/POST flow, Origin rejection, and clear unavailable behavior when Google credentials are absent. No real email was sent.
